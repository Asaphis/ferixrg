# FerixRG Entry-Flow Visual Brief

## Purpose

Create approval-only UI/UX concepts for the public entry experience before implementation. The product must allow visitors to understand and analyze a public storefront before account creation, while supporting a short verified-account onboarding path into the existing workspace.

## Required Visual Set

| Artifact | Required content |
| --- | --- |
| Desktop landing concept | Header, hero, in-hero public URL analyzer, product transformation, trust platforms, core capability modules, AI assistant, redesign comparison, reporting, workflow, audiences, and final CTA. |
| Mobile landing concept | The same landing content in a vertical mobile order; the hero must keep the URL analyzer and both primary actions visible. |
| Desktop account-flow concept | Split brand/product panel and an account card showing Sign Up, Sign In, verification, and the four concise onboarding steps. |
| Mobile account-flow concept | Single-column account and onboarding screens with the same fields, status states, actions, and no split visual panel. |

## Information Architecture

1. **Explore first:** Landing → paste store URL → analysis results → optional store connection for redesign and publishing.
2. **New account:** Get Started → Sign Up → Email Verification → four-step onboarding → Dashboard.
3. **Returning account:** Sign In → Dashboard, without recurring onboarding.

## Required Account and Onboarding Details

Sign-up includes full name, email, password, visible password requirements, Google alternative, legal consent, and Sign In route. Sign-in includes email, password, Forgot password, Google alternative, and Create Account route. Verification includes Open Email, resend status, use another email, successful verification, and Continue. Onboarding covers user type, goals, platform choice, first-store URL or optional platform connection, completion confirmation, and non-blocking Skip Setup.

## Visual Direction

Use the approved FerixRG system: quiet mineral public-site background, Ferix Blue #155EEF for decisions, dark operating-interface previews, Manrope utility typography with restrained editorial serif moments, ample whitespace, meaningful component hierarchy, and no generic finance-dashboard imagery. Present actual storefront intelligence, evidence, health scores, responsive checks, redesign comparison, and safe publish context.

## Reference-Led Landing Composition Revision

Use the supplied reference image only as a compositional and interaction guide. The revised FerixRG landing concept should sit inside a large rounded, warm-white canvas on a restrained pale-grey field. It needs a narrow compact header, a large rounded soft-grey hero panel, left-aligned editorial headline, concise action row, and a layered storefront-intelligence product visual on the right. The visual must remain FerixRG-specific: use a dark product analysis/re-design preview rather than the reference’s unrelated product imagery.

Directly beneath the hero, include an intentionally animated horizontal marquee for supported platforms. The visual mockup should show repeated platform tiles or marks for **Shopify, WooCommerce, BigCommerce, Shopware, Custom / Headless, and URL Analysis** moving across the band, with an accompanying label explaining that visitors can start with public storefront analysis without connecting a store.

## Reference-Led Mobile Parity

The mobile landing visual must not omit desktop content. It should reflow the compact header, FerixRG hero, **Analyze Your Store** and **Explore Platform** actions, platform marquee, product analysis/re-design scene, all five problem cards, the six-part solution system, AI assistant prompts, 72-to-94 redesign comparison, Analyze / Discover / Improve / Publish workflow, Store Health metrics, and final conversion CTA into one readable phone scroll. The mobile marquee can become a horizontally clipped, visibly moving sequence of platform chips; this is a layout change only, not a content reduction.

## Shared Desktop–Mobile Visual Module System

The revised concepts use one product-story system. Both desktop and mobile must include the same modules: **hero and URL analysis**, **supported-platform marquee**, **store-outcome proof strip**, **flagged-store problems**, **AI assistant guidance**, **before/after redesign evidence**, **Analyze / Discover / Improve / Publish workflow**, **Store Health report**, and **final acquisition CTA**. Every image used at desktop has a corresponding mobile equivalent: the hero storefront-intelligence composition becomes a stacked product montage; the proof row becomes a horizontal scroll sequence; outcome cards become vertical featured cards; and before/after surfaces remain paired in the same order.

## Editorial Proof and Outcomes Translation

The new reference contributes an editorial sequence rather than an IT-services identity. In FerixRG it becomes: a **Store outcomes** band with operational figures such as `91/100 Store Health`, `18 improvements surfaced`, and `2 redesign alternatives`; a **What changed** feature story using a storefront redesign image and issue list; **evidence cards** showing a responsive test, AI redesign alternative, and report view; and the existing platform marquee. No customer testimonials, client success claims, or invented reviews are used.

## Visual-Element Parity Audit

The mobile concept must retain the desktop master’s actual **hero dashboard/browser/phone montage**, **five product-image problem cards**, **What changed storefront scene**, **assistant icon and prompt details**, **responsive device evidence image**, **AI redesign storefront image**, **donut-report image**, **paired before/after storefront images**, **report icons and metric bars**, **platform icons/chips**, and **small dividers, badges, arrows, and supporting proof marks**. These elements are not optional decoration; every one must appear in a mobile counterpart using the same source image treatment where space permits.

The available product assets support true responsive composition: `ferixrg-hero-workspace.png` is the dark analysis-and-storefront workspace scene for the hero; `ferixrg-redesign-compare.png` is the full two-browser before/after redesign surface for the comparison module. These should be placed as independent images within their specific mobile cards, never as a cropped whole-page background.

## Shared Art-Direction Contract

The current desktop master establishes the intended visual language and must remain the source of truth for the matching mobile concept. The common system is: a pale mineral-grey outer field; a warm-white rounded canvas; blue FerixRG decisions; small uppercase blue labels; bold geometric sans headlines; fine warm-grey dividers; rounded white cards; tiny blue/green/orange proof badges; and consistent simple product visuals.

The hero is a deliberate **product montage**, not a generic screenshot. It pairs text and dual actions with layered elements: an analysis-health card, a storefront browser frame, a narrow phone preview, an evidence/recommendation card, a subtle connector/dotted line, and a small blue AI-ready badge. On mobile, these same individual objects must remain visible below the hero copy in a vertical overlap, not be replaced by unrelated product photography or a single flat image.

The platform band must retain its compact label, arrow/motion cue, lightly bordered logo chips, and divider treatment. Below it, the outcomes strip, problem cards, feature story, AI band, three evidence cards, comparison, workflow, report, and CTA must all use the same card geometry, border treatment, badges, micro-labels, arrows, and image style on desktop and mobile. Mobile changes only the grid and overlap arrangement; it does not change the visual vocabulary.

## Rich Visual Restoration Layer

The shared design must retain the visual richness of the original master. Platform support is represented by recognisable logo tokens, not plain text chips: a green Shopify bag mark, purple WooCommerce wordmark, black BigCommerce geometric mark, blue Shopware curve, Custom / Headless code mark, and URL Analysis link mark. They appear inside the same animated bordered band at both widths.

The hero montage keeps the dark analysis window, browser storefront, phone preview, score dial, connector line, AI insight card, redesign impact card, and blue AI-ready badge. The proof sections preserve real product-image surfaces and visual objects: store thumbnails in issue cards, responsive device frames, redesigned storefront previews, a donut/report graphic, score trend lines, status dots, and download/arrow affordances. These are designed objects in separate cards, not decorative page backgrounds, and must survive on mobile in the same module order.

## Hero Motion System

The main headline, URL analyzer, and actions remain visually stable. Motion is reserved for the hero montage: the dark workspace drifts vertically by 6–10px over 8.4 seconds; the browser frame drifts in the opposite direction over 9.2 seconds; the phone preview rises and settles over 7.6 seconds; the AI insight and redesign-impact cards each have independent 5–7px float loops with different delays; the blue AI-ready badge has only a subtle 2px settle; and the dotted connector line has a very slow opacity pulse. Decorative dots and micro-badges may drift by 2–4px at different phases.

All movement uses `transform` and `opacity`, a slow custom ease-in-out, and `prefers-reduced-motion` to disable non-essential animation. On desktop, pointer movement can add a maximum 4px parallax offset to the montage only. On mobile, the same floating objects remain but no pointer parallax is applied. No element should scale from zero, bounce, or animate the copy, buttons, layout, or scroll position.
